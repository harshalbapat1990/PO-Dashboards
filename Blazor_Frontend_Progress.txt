2. DEVELOPMENT PLAN (NEXT WORK SEQUENCE)
==================================================

1. Confirm repository foundation
   - Verify origin/fork, upstream expectations, branch setup, and secret
     exclusions.
   - Confirm README prerequisites/startup/config guidance and baseline API
     and Vue behavior.

2. Close API and authentication gaps
   - Compare Blazor headers, token callback/storage, expiry handling, and
     401 flow with the Vue client and Functions API.
   - Fill identified client gaps, then verify anonymous and authenticated
     calls.

3. Finish read-only App Catalog parity
   - Complete Help and any missing account/error/not-found behavior.
   - Standardize loading, empty, failure, and unauthorized states.
   - Compare list, detail, and navigation workflows with Vue.

4. Finish write workflows
   - Verify create, update, delete, and review behavior, role restrictions,
     and failure handling.

5. Establish shared visual foundation
   - Implement and check responsive layouts, themes, keyboard navigation,
     visible focus, accessible status, and data presentation.
   - Label prototype/derived health data accurately.

6. Build dashboard and chart capabilities
   - Add pinned local Chart.js and reusable interop lifecycle.
   - Add configurable dashboard modules and executive, sprint, and security
     shells using only available or clearly mocked data.

7. Expand backend metrics separately
   - Define and implement required Azure Functions and MongoDB contracts
     before representing additional Product Health metrics as real data.

8. Validate and decide transition
   - Build/run Blazor and API; exercise auth and parity workflows; validate
     responsive, accessibility, and chart scenarios.
   - Decide between side-by-side hosting, Blazor default, or Vue retirement
     only after route, authentication, and workflow parity is demonstrated.
