1. HOW TO USE THIS TRACKER
==================================================

Task status:
[ ] TODO        Work has not started.
[~] IN PROGRESS Work is underway.
[x] IMPLEMENTED Source changes are present; acceptance is not yet verified.
[V] VERIFIED    Stage acceptance checks passed and evidence is recorded.
[!] BLOCKED     Work cannot proceed; record the blocker and owner/action.

For each task, update its status and append evidence/date in the Evidence
column. Do not mark a task VERIFIED based on source inspection alone. A stage
is complete only when all required tasks are VERIFIED and its exit gate passes.
Keep later stages TODO/BLOCKED until prerequisite stages are complete.

Evidence format:
Evidence: <test/check/result, artifact or source reference> | Date: YYYY-MM-DD

Except where dated evidence is explicitly recorded below, this tracker does not
claim a build, runtime, integration, database, or test check has passed.

  initialization/reset and recovery. There is no MongoDB data migration.
- Preserve the pipeline: GitHub/Azure DevOps source data → normalized data →
  metrics → health scores/history → management aggregates → AI inputs/outputs.
  Dashboard requests read persisted application data, not external providers.

  a prerequisite task; do not silently select a formula or mark the metric
  complete before its definition is approved.
- Keep AI behind a provider-neutral server-side boundary; provider credentials
  must be configured outside source control.

  starting dependent stages. Track blockers with cause, owner, and resolution
  action rather than silently skipping tasks.
