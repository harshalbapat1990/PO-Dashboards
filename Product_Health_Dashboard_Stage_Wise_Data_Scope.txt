PRODUCT HEALTH DASHBOARD
STAGE-WISE DATA SCOPE
==================================================

1. PURPOSE
==================================================

This document defines the data that the Product Health Dashboard will contain and display at each implementation stage.

The key distinction is between:

1. Source data pulled from GitHub and Azure DevOps.
2. Normalized data stored by the application.
3. Metrics calculated by the application.
4. Health scores derived from metrics.
5. Management-level aggregations.
6. AI inputs and outputs.

The data model should be built progressively so that future dashboard capabilities can be added without redesigning the entire database.

- Security metrics

- Deployment metrics
- Testing metrics
- Release information
- Risks
- Recent significant changes

AI OUTPUT

- What happened?

HEALTH EXPLANATION

- Why did the score change?

RISK IDENTIFICATION

- What should the Product Owner be concerned about?

RECOMMENDATIONS

- What should the team investigate?

RELEASE CONFIDENCE

- Does the available data indicate increasing release risk?

Example:

"Product health declined from 87 to 76 primarily because sprint carry-over increased, three high-severity vulnerabilities remain open, and PR review time increased by 32%."

==================================================
17. KEY DESIGN PRINCIPLE
==================================================

The system should pull and retain sufficient source data to support future metrics without repeatedly changing the underlying integration architecture.

The dashboard should not directly depend on GitHub or Azure DevOps for every screen load.

Instead:

GitHub / Azure DevOps
        |
        v
Synchronization
        |
        v
PostgreSQL
        |
        v
Normalized Data
        |
        v
Metrics
        |
        v
Health Scores
        |
        v
Blazor Dashboard
        |
        v
AI Insights

This provides:

- Fast dashboard performance
- Historical trends
- Cross-system analytics
- Resilience to external API outages
- Reduced external API dependency
- Consistent metric calculations
- A stable foundation for future dashboard modules
